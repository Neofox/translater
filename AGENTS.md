# AGENTS.md

## Project

A streaming EN↔KO-first translator and language-learning tool, written in Go and deployed to Vercel. The server is `net/http` with templ templates; the page is server-rendered HTML driven by htmx 4 and its `hx-sse` extension plus a set of plain ES modules (no framework, no bundler). Tailwind v4 compiles the stylesheet. The server calls the OpenAI Responses API through the official Go SDK (`openai-go`) with strict structured output, and parses the streamed JSON itself.

`TRANSLATE_MODEL` is one exact, deployment-controlled OpenAI model id (default `gpt-6.1-terra` on the Fast tier with reasoning `none`, chosen for time-to-main-translation first and explanation quality second). There is no fallback model. A legacy `openai/` prefix is rejected as a configuration error, not stripped.

## Layout of the repository

- `main.go`: routes and server start-up. `GET /` (page), `POST /translate` (one streaming run as `text/event-stream`), `POST /warm` (free warm-up), `POST /speech` (pronunciation PCM), `POST /prefs` (re-rendered language chip bars), and the hashed `/static/` assets.
- `shared/translation/`: the language-neutral contract. Mustache prompt templates, few-shots, strict result JSON Schemas, UI strings, languages, limits, preference rules, `meta.json` (`cacheVersion`, default model) and the golden request bodies in `fixtures/`. `embed.go` embeds it into the binary; `README.md` defines every template variable and the request body. There is no generated copy.
- `internal/contract`: loads the embedded contract (strict Mustache rendering, few-shots, schemas, strings).
- `internal/prompt`: turns a validated request into the exact Responses request body (`BuildRequest`, eval variants in `BuildVariant`), including `liveText` and the user blocks, and derives the cache key.
- `internal/config`: `TRANSLATE_MODEL`, `TRANSLATE_REASONING`, `TRANSLATE_SERVICE_TIER` resolution.
- `internal/llm`: sends the prebuilt body with `openai-go`, streams output-text deltas and classifies provider failures.
- `internal/jsonstream`: incremental scanner for the structured-output JSON as it arrives in deltas.
- `internal/translate`: `POST /translate` and `POST /warm`. Maps JSON paths to SSE events, renders result partials with templ, validates the final document against the schema (`santhosh-tekuri/jsonschema`) and caches results in an LRU (`hashicorp/golang-lru`, 50 entries per instance).
- `internal/learning`: learning side selection (`Side`) and exact phrase/grammar range resolution (`Prepare`).
- `internal/speech`: `POST /speech`.
- `internal/telemetry`: optional, content-free Langfuse traces over OTLP/HTTP.
- `internal/prefs`: the `nt.preferences` cookie.
- `internal/web`: the page (templ), view helpers, static asset hashing and serving. `internal/web/ui` holds the `Pill` and `Tag` primitives; `internal/web/icons` the lucide icons (generated by `cmd/syncicons` from the `lucide-static` npm package).
- `internal/fakeopenai` and `cmd/fakeopenai`: a fake Responses and speech API that replays `e2e/fixtures/results` so tests never make paid calls.
- `web/static/`: `js/` client modules (see `web/static/js/README.md` for each module's role), `css/` (`input.css` Tailwind entry, `base.css` theme and component rules, pinned `pretendard.css`, compiled `app.css`), vendored `htmx.min.js` and `hx-sse.min.js`, and the favicon. `web/assets.go` embeds them.
- `cmd/`: `request` (prints the production request body for the evals), `smoke` (billed production smoke), `assetsize` (gzip budgets), `syncicons`.
- `e2e/`: the Playwright suite, the visual regression suite (`e2e/visual`) and the perf harness (`e2e/perf`).
- `evals/`: promptfoo quality evals.

## Architecture notes

- Two translation modes: **sentence** and **word**, auto-detected on the client (`detectIntent` in `composer.js`: ≤3 tokens AND ≤24 chars → `word`, else `sentence`).
- Three tone modes: `friends` (slang/반말), `casual` (해요체), `professional` (하십시오체).
- Prompts are multi-message conversations: `developer` (language rule) → `system` (instructions) → few-shot `user`/`assistant` → actual `user` input.
- A run is an htmx request of `#translate-form` (`hx-trigger="nt-run"`, `hx-sync="this:replace"`). The form holds only hidden inputs, so the textarea is never part of a swap. The response is a stream of named SSE events that `hx-sse` dispatches as DOM events on the form: `nt-source-lang`, `nt-target-lang`, `nt-headword` (word intent), `nt-main-delta`, `nt-main-ready`, `nt-text-delta`, result partials, `nt-learning` (sentence intent, just before the end) and exactly one `nt-done` or `nt-error`. Every payload carries the client's run id; `stream.js` drops events of a superseded run.
- Main Copy and its keyboard shortcut become available when the main JSON string closes (`nt-main-ready`), while learner details continue streaming. Preserve the current-request and error guards (`copy.js` `requestKey`). Listen and alternative Copy still wait for a completed result.
- OpenAI routing: `OPENAI_API_KEY` is read per request; a missing key is a classified configuration error. `TRANSLATE_REASONING` is `none`|`low`|`medium` (default `none`), `TRANSLATE_SERVICE_TIER` is `default`|`fast` (default `fast`; Fast is OpenAI priority processing at 2× price, and OpenAI silently serves Standard when Fast is unavailable, reported in the response's `service_tier`). The app never sends a fallback model and makes zero retries, so a paid retry requires explicit user action. OpenAI reports exhausted credit as 429 `insufficient_quota`, classified as `budget`, not rate limiting. Vercel AI Gateway is not used. An invalid translation or speech setting never takes the page down: each run answers with the localized configuration error, naming only the variable.
- Caching and provider options: OpenAI prompt caching uses `prompt_cache_key` and explicit 30-minute cache options; the stable final-user reminder ends with an explicit breakpoint and all live source/context/refinement content follows in a separate text part. Every request sends `reasoning.effort`, `service_tier` and `store: false`. Hidden reasoning cost seconds of TTFT and billed tokens on every model tried, so `none` is the default; `gpt-6.1-sol` has no `none` effort (minimum `low`). The server LRU key includes model, reasoning and tier.
- Langfuse is optional and activates only when both `LANGFUSE_PUBLIC_KEY` and `LANGFUSE_SECRET_KEY` are non-blank. Traces are content-free generations built on the OpenTelemetry Go SDK: only the runtime-context allowlist (intent, mode, languages, `hasContext`, refinement count, request kind, input length bucket, `isPolish`, prompt version, model, reasoning, tier, trigger and the analytics run ids) plus usage. Source text, context, refinements, prompts, outputs, raw bodies and provider metadata must never be added to telemetry; the telemetry test pins the allowlist. Configure environment/release through `LANGFUSE_TRACING_ENVIRONMENT` and `LANGFUSE_RELEASE`. Telemetry failures remain non-fatal. LRU hits make no OpenAI call and create no trace; speech is never traced.
- Billing: OpenAI is authoritative for billed usage and cost (paid from the monthly OpenAI credit). The application does not calculate cost; Langfuse may show its own estimate. Evals estimate cost from token usage with `evals/pricing.ts` (Standard list prices, Fast ×2); update it when prices or models change.
- Client debounce (`composer.js`) is 800ms, shortened to 400ms when the raw text ends in sentence-final punctuation or an emoji (optionally followed by closing quotes/brackets); a trailing space/newline or partial Korean jamo keeps 800ms so mid-sentence pauses don't fire early. IME composition never schedules a run. Input changes abort the in-flight run, and the server cancels the upstream stream when the request context ends. Vercel does not cancel a function when the browser disconnects, so there the first failed write to the departed client is the signal; a superseded speech request runs upstream until it completes. The client calls the free `POST /warm` (no OpenAI request) on `focusin`/`visibilitychange`, at most once per 2 minutes, so a cold instance boots before the user submits. Paste skips the debounce and blur flushes a pending run. Enter and Shift+Enter always insert a newline, including while a translation is pending; Cmd/Ctrl+Enter force-runs and replaces any pending debounce. Escape clears the source (and focuses it) only when focus is in the source textarea or on the page itself (`body`); an open popover, the Adjust panel and the mobile learning surface take Escape first and close, and Escape on any other control never clears. Text typed before the client modules run is picked up as if typed afterwards; text the browser restores on reload or back/forward never starts a paid run.
- Refine + context: a run carries optional `context` (sentence + word), `refinements` + `previousMain` (sentence only, max 3 refinements of which at most one is free-text). They are injected only into the FINAL user message as `<context>`/`<adjustments>` blocks; the explaining system lines are UNCONDITIONAL so the prefix cache stays intact — keep them that way. Refine chips are toggles (`aria-pressed`); toggling one off removes that adjustment and re-runs (the LRU makes it cheap). A failed refine rolls back via an internal snapshot stack in `refine.js` (no user-facing undo control). Editing the input clears refinements; context is sessionStorage-sticky (`nt.context`). All live text (source, context, refinements, previousMain) passes through `liveText` in `internal/prompt`, which turns pasted `<source>`/`<context>`/`<adjustments>` tags into look-alike `‹…›` quotes so they cannot forge block boundaries (a fake `</source>` previously made the model drop the text before it). The data-not-instructions lines also require covering ALL source text, including markup- or instruction-like parts, because models otherwise silently drop injected lines. `detail-guidance` carries CHARACTER ACCURACY (hanja only for Sino-Korean words, never invented for native words) and GRAMMAR ACCURACY (vowel harmony, adnominal tense, ending vs particle, exact conjugated grammarHighlights) rules; their examples deliberately avoid the eval cases.
- Run analytics: every `POST /translate` carries telemetry-only form fields (`analyticsSessionId`, the run it supersedes, the input revision and the trigger). The server puts them in Langfuse metadata only.

## Contextual learning

- `SentenceResult.learningPhrases` carries exact quotes, glosses, counterpart `sourceTexts`, base forms, literal/natural meanings, grammar, omissions, usage notes and character origins in the INITIAL translation request. All response fields remain required for strict structured output; inapplicable facts use empty strings. `grammarHighlights` quotes only noteworthy endings, conjugations or grammatical constructions inside each phrase, with empty arrays for ordinary vocabulary. Prefer one to three useful points per sentence, never underlining every word. `internal/learning.Prepare` resolves ordered, grapheme-safe exact ranges for phrases, counterparts and grammar annotations on the server, which sends them as UTF-16 offsets (no text) in `nt-learning`. Ambiguous or invalid annotations stay unmarked; an annotation requires a grammar explanation. No model-counted offsets.
- Phrase inspection is local page state only (`learning.js`). There is no learning request, More detail button, loading/retry path or enrichment cache. Phrase taps and breakdown rows reveal the initial response; they never issue an LLM request, including for older or incomplete maps. One learning state owns selection and invalidates on edits/settings/refinements/Clear/errors/pagehide; an edit that changes only the source's surrounding whitespace keeps it, with the source offsets moved by the leading whitespace (`forSource`). Never persist source, output or analysis in storage/logs/telemetry. The translation LRU remains the only server result cache.
- Keep `main` before the phrase details in the JSON schema and prompt. Copy still enables when the current main string closes, while rich phrase details and other metadata continue streaming. Inspectable details, Listen and Refine retain their whole-result/current-request guards. Bump `cacheVersion` in `shared/translation/meta.json` after response-contract changes so earlier results miss the cache.
- Learning follows the non-fluent language: when the reported target equals the UI language and the reported source differs, analyse the original source; otherwise analyse the target (including same-language polishing). `learning.Side` selects this deterministically, matching the detail prompts. `learningPhrases.text` quotes that side in order; `sourceTexts` quotes the opposite side despite its legacy name. The selected side is the primary text for sentence ranges and exact UTF-16 validation. Counterpart spans correspond to the opposite text and may reorder or be absent. Validate exact slices, grapheme boundaries and nonoverlapping primary ranges; incomplete coverage is indicated. Input limits are 4,000 source and 16,000 target characters. A learning-only error keeps translation actions usable.
- The main text preserves plain text and native selection. A short stationary single gesture can inspect a target offset, after a 400ms selection grace period; drag, long press and double-click do not inspect (`inspect.js`). The 44px inspector chunk buttons provide keyboard access. On desktop, when learning the original source, the target stays plain and non-tappable; use the prepared reference rows. Mobile target taps open the source learning view. The source textarea remains a native editor. A short stationary primary-pointer tap within a prepared source grammar underline opens its owning phrase after the same 400ms grace period. Plain source text, drag, double-click, long press, noncollapsed selection and subsequent typing/navigation/scroll/blur retain editing behavior and cancel pending inspection. Hit-test the synchronized mirror's visible underline rectangles without adding an intercepting overlay or preventing native pointer defaults. The source highlight mirror uses the selected primary range for source learning and opposite-side spans for target learning. It also renders prepared grammar underlines when learning the original source, before phrase selection. The selected range uses its background highlight without another underline. It is an inert synchronized mirror; source inspection listens on the textarea and tracks the matching pointer through release even when keyboard focus reflows the pane. Desktop phrase inspection leaves source focus in place. Retain the same textarea node, cursor, wrapping and scroll.
- Breakdown is a continuous list across the whole message, never sentence pagination. Selecting a row expands its details inline with `aria-expanded`; the remaining rows stay visible. One phrase is expanded at a time and the same source/main highlights follow it. There is no separate Learning tips UI or response object: grammar, vocabulary/cultural nuance (`usageNote`) and useful CJK `characters` belong to their owning phrase. Word results keep grammar, usage `notes` and character origins inside the dictionary entry. Every generated field is required; empty strings/arrays mean inapplicable.
- The desktop workspace reuses the source-side reference for phrase inspection and dictionary data. On mobile (stack/split/laptop/book), tapping the translation opens a full-size learning reading surface with Close/Escape, independent scrolling and the original Copy/Listen dock at its bottom. There is no mobile Breakdown button, minimize control or automatic keyboard/short-height minimization. Background header/source/result controls are hidden or inert; closing restores focus to the translated word or main text, or restores the exact source caret/direction/scroll when opened from a source underline. Keep the same textarea and action nodes mounted. Hide the background reference while the mobile reading surface is open so learner data occurs once.
- Mobile text taps can inspect any meaningful phrase, including ordinary words without grammar underlines. Only grammar annotations are underlined. When learning the original source, a target tap maps through counterpart spans when possible, otherwise opens the source overview. Desktop retains sparse grammar hit targets and a plain fluent target when learning source. Drag, double click and long press retain native selection; a single stationary gesture waits the existing selection grace period. Keyboard Enter/Space opens mobile learning from the main text.
- Desktop source is flat and transparent, 20px body text. The reply/count footer is quieter at 14px, retaining 44px actions. A single closing rule under the whole composer becomes violet on focus; no rule between source and footer. Reference starts after 32px whitespace (less at short heights), with smaller phrase/gloss typography, no row rules, and inline selected details. Keep alternative-row separators.
- Refinements live beside Tone in the header, separated by an **Adjust** label/divider. Show chips directly only when their measured width fits; otherwise use an Adjust disclosure with active summary/dot (`adjust.js`). Keep one mounted refine row so drafts/focus survive width changes. Close the full mobile learning view to return to Adjust and the editor. Adjust uses an anchored floating panel (`float.js`) in desktop, mobile portrait and split layouts, with no header height reservation and constrained to avoid Copy/Listen. It sits under its trigger at every width: `float.js` computes viewport coordinates and corrects for any ancestor that becomes the fixed panel's containing block, so the centred shell's header edge never offsets it on wide screens. Only the dedicated tight-keyboard Custom editor reserves header space; other panels wrap chips; short heights use a scrolling chip row or the Custom editor alone. A tight keyboard retains only the Custom input with 44px Apply/Close. Close preserves the draft and returns source focus. Outside dismissal runs after click actions so panel reflow cannot swallow Copy. Caps, current-result guards and rollback remain. UI language is under **Settings**. Alternatives remain open with their own explanations and Copy/Listen. Portrait Paste/Clear remain text-labelled beneath the multiline editor. In narrow split/book panes, source Paste/Clear/reply context share a persistent bottom baseline with the target Copy/Listen dock, with editor and reference content above. Preserve the same source/action nodes, safe-area padding and the matching server-rendered first paint.
- Stable selectors: `learning-inspector`, `learning-panel`, `learning-chunk`, `selected-phrase`, `source-highlight`, `adjust-button`, `settings-button`. Open Adjust before interacting with refine chips when the header is compact; open Settings before changing UI language. Phrase inspection has no request transport; browser tests still route speech and translation to the fake to prevent paid calls.
- Word results automatically show their dictionary in workspace/split/book reference panes, without moving source focus (`dictionary.js`). The target word stays neutral and unadorned when that reference is already visible. Clicking/keyboard-activating `[data-testid="word-details-trigger"]` focuses and scrolls that reference on every activation, with a highlighted dictionary heading; compact layouts open it on demand and restore the word trigger on close. No separate Word details row and no learning generation. A synonym starts a new lookup.
- Exact quotations and phrase order disambiguate repeated primary text. If an overlapping or out-of-order quote makes the full sequence impossible, retain only uniquely matched, disjoint quotes in source order and mark incomplete coverage; never discard independent valid details or choose an arbitrary repeated match. Ambiguous/missing counterpart quotes produce no source highlight. Grammar annotations resolve only unique exact slices within their parent phrase, preserving grapheme boundaries, ordering and nonoverlap. Keep native selection and double-click/long-press behavior intact. `internal/learning/testdata/corpus.json` is frozen regression data for these rules.
- Underline only prepared grammar-highlight spans, never all phrase spans, the whole sentence or punctuation-only tokens. Ordinary vocabulary stays plain; its full details remain available from the phrase rows and mobile text taps. The word-details trigger retains its separate dictionary affordance. The selected phrase has a background highlight without an additional underline. Punctuation-only analysis rows are omitted without changing the original chunk selection indices. Do not restore helper paragraphs explaining tapping/Breakdown. Keep Adjust with Tone in the header, use spacing above Alternatives; keep separators between alternative rows only.
- There is no Breakdown button in any layout, including streaming and older results. Desktop shows prepared reference rows; mobile opens learning from the text. The initial response already contains the complete phrase facts, so there are no enrichment buttons, loading skeletons or paid learning retries. Screenshot helpers must exclude infinite pulse animations when waiting for transitions.

## Pronunciation and result transitions

- `internal/speech` serves `POST /speech`: one OpenAI text-to-speech request per Listen tap with zero retries, no telemetry and no logging of input text, provider errors or audio. It validates the WAV framing/format, discards metadata, and answers validated mono PCM16 (`audio/L16;rate=N;channels=1`, with `Content-Length`) after generation completes.
- `SPEECH_MODEL` chooses one exact OpenAI speech model (default `gpt-4o-mini-tts`; an `openai/` prefix is rejected). `SPEECH_VOICE` is optional (default `marin`). OpenAI speech has no language parameter, so the voice instructions name the language (gpt-4o-mini-tts and newer; `tts-1`/`tts-1-hd` do not support instructions). Change the deployment env, redeploy, and reload to switch. No fallback or automatic retry. A replacement model must return mono PCM16 WAV (8–48 kHz).
- `speech.js` unlocks Web Audio synchronously on tap, streams through `PcmPlayer` (`pcm.js`), stops on edits/settings changes/pagehide, and caches only completed audio in a bounded page-memory cache. One page-wide voice: starting another Listen cancels the previous loading/playing request; keep owner cleanup guarded by identity.
- Speech limits: 4,000 input characters, 8 MiB audio, 90-second server timeout.
- Copy confirms on every layout (`copy.js`, `base.css`): a pressed `:active` state that also shows on touch (a passive `touchstart` listener enables it on iOS; no scale under reduced motion), then for 1.5 s the check icon in violet in place of the copy icon on the tonal accent surface, the name and label "Copied", and a polite status region (created on the first copy) that announces it. Main and alternative Copy buttons mount both icons; the inactive one is `hidden`.
- Main and alternative Copy/Listen controls render their real, static content during loading; do not replace known buttons or refinement chips with skeletons. Copy enables when the current main string is complete; Listen and Refine remain disabled until the whole current non-error result completes. Both Listen surfaces use the same language, stale/pending guard, and settings reset key. The result view transition (`transition.js`) starts only at completion/error, never for streaming deltas; with reduced motion no transition starts.

## Streaming presentation

- `stream.js` interpolates provider bursts on grapheme boundaries for at most 100ms per burst. It changes only the displayed main text, never the result state, Copy text/readiness, run identity or server behavior. Flush when main closes, on completion, result focus/pointer selection and returning to a visible tab. A new run cancels old frames, and an aborted main freezes. Reduced motion shows live text directly. Preserve native selection.
- Main text uses normal wrapping; never pretty/balanced wrapping during or after streaming. The cursor occupies zero inline width and stops once main is ready; hide it for reduced motion. Supporting details fade in for 160ms with no height animation and no animation under reduced motion. Known controls remain mounted with their real content.
- The main explanation is secondary 14px/1.5 type, a 12px gap below the main, with a 64ch maximum and a permanent two-line minimum when present. Two neutral placeholder lines reserve that measure while waiting; one-line explanations keep the minimum so following content does not jump upward. Longer explanations grow naturally. Infinite skeleton animations must be excluded from screenshot settling waits.

## Styling

Tailwind v4 with a bi-accent palette defined in `web/static/css/base.css`. Only templ files and client modules are scanned (`input.css`), so every class string lives in a `.templ` or `.js` file. `app.css` is compiled and committed (`make css`).

- `--color-accent` / `--color-accent-soft` — **violet**, "action / primary / feedback". Use for: Mode toggle active state, streaming indicator, brand dot, current-mode chips, "Sentence" intent hint, cursor pulse.
- `--color-warm` / `--color-warm-soft` — **amber**, "learner / scholarly / dictionary". Use for: learner section labels (grammar / vocab / hanja·kanji·hanzi), CJK word glyphs, dictionary section headers (POS, Primary meaning, Etymology, Notes, Synonyms), the "Context" label, "Dictionary" intent hint.
- `--color-ink` / `--color-ink-soft` / `--color-ink-dim` — neutral grey scale for structure, body copy, borders. Never stack three greys in one control; prefer `text-ink` on `bg-panel` with `border-border` over `text-ink-soft`.

Primitives live in `internal/web/ui`:

- `Pill` (tone `neutral | accent | warm`, size `sm | md`) — the canonical button-chip shape. Tone tints hover border + inline `<svg>`. Used by Copy and the learner pills. Reach for it before hand-rolling another `inline-flex rounded-md border bg-panel ...` button.
- `Tag` (tone `neutral | accent | warm`) — small uppercase chip. Used for register badges, mode chips, POS register tags.

Rules of thumb:

- Never use `text-ink-soft` as button rest color — it compounds into grey-on-grey-on-grey. Use `text-ink` and let hover add the tone.
- Don't introduce a third accent hue. If something needs emphasis and isn't "action" or "learning", it's probably structure (neutral).
- Uppercase section labels (`tracking-wide text-xs font-semibold`) belong to the amber family when they introduce learner content, the violet family when they're state indicators.

The production stylesheet inlines the pinned Pretendard font-face declarations (`pretendard.css`, `font-display: optional`; font subsets keep their original CDN URLs, license in `web/static/fonts/OFL.txt`). Slow connections must not trigger a late font swap. The script and stylesheet gzip budgets (`make size`) are targets, not reasons to cut a feature.

### Driving the language chip bars

Each panel renders a chip bar: a `role="group"` of big `Pill` chips (source bar = `auto`/`en`/`ko` + one persisted "recent" chip; target bar = `en`/`ko` + recent) plus a trailing `More…` trigger. Click a chip directly by `data-value` — no dropdown needed for the fixed languages:

```bash
cmux browser --surface <s> click --selector "[data-testid='lang-chip'][data-value='ko']"
```

For a language not already shown as a chip, open the more-languages trigger first, then click the option in the listbox it opens (`browser select` does **not** work on it):

```bash
cmux browser --surface <s> click --selector "[data-testid='lang-more-trigger']"
cmux browser --surface <s> click --selector "[data-testid='select-option'][data-value='ja']"
```

Picking a language this way promotes it to the recent chip on that bar (stored in the preferences cookie), so it's directly clickable next time.

Disambiguate source vs. target bars via the group's `aria-label`:

```bash
cmux browser --surface <s> click --selector "[aria-label='Source language'] [data-testid='lang-chip'][data-value='en']"
cmux browser --surface <s> click --selector "[aria-label='Target language'] [data-testid='lang-more-trigger']"
```

**Narrow panels collapse the bar.** The language group is a CSS query container: source chips expand at 320px, target chips at 280px of actual bar width after toolbar actions. All chip candidates render in the server HTML; below those widths CSS hides inactive chips, leaving the SELECTED chip plus `More…` visible. A selected non-fixed language becomes the recent chip immediately. Other languages (including `auto` for the source bar) remain available in the listbox, which mirrors the visible chips. This also handles split windows and folded displays. Automation should check whether a chip is visible and otherwise use `lang-more-trigger` + `select-option`, rather than assuming DOM presence or viewport width guarantees a visible chip.

**Optional fold layouts.** With Safari's Device Posture and Viewport Segments feature flags enabled, book posture places source and result in separate horizontal segments. Laptop posture places the result above the fold and input below it; `layout.js` measures the header offset so the boundary matches the physical fold. Unsupported browsers keep the standard responsive layout. These layouts use CSS feature queries, never device-name detection.

### Workspace layout

`layout.js` (`decideLayout`) chooses the layout and publishes it as `data-layout` and flags on the shell. The desktop `workspace` mode starts at 1100px of usable width: source on the left, result on the right, with one result reading column. The desktop shell is centered at a maximum of 1536px, with excess width outside the paired panes. ### Gotchas discovered

- **Ephemeral refs**: cmux snapshot refs (`[ref=e123]`) change between commands. Never hard-code them in scripts; always prefer `data-testid`, `aria-label`, or `eval` with `querySelector`.
- **Chips vs. dropdown**: The visible chip bars are plain buttons, not a combobox — only the trailing `More…` trigger opens a listbox (`role="listbox"`, `role="option"`, `aria-expanded`, `aria-selected`). Prefer clicking chips directly; only fall back to the listbox for languages not already promoted to a chip.
- **Auto-swap reset**: The auto-swap logic resets its one-shot flag when the input is cleared. If a test needs to re-trigger swap behavior, clear the textarea first (via the Clear input button), then type the new language.
- **Auto detection**: under Auto source, the client counts CJK scripts and treats any Latin-script text as `en` until the model's `nt-source-lang` relabels the Auto chip (`web/static/js/README.md`).

### The e2e suite

`e2e/` is a black-box Playwright suite: 18 projects (nine folded/unfolded phone, iPhone and MacBook viewports × Chromium and WebKit), tagged `@core`, `@context`, `@layout`, `@learning`, `@word`, `@refine`, `@speech`, plus `@visual`, `@prod` and `@review`. Each Playwright worker gets its own fake OpenAI server (`go run ./cmd/fakeopenai`) and app server (`go run .`) with `OPENAI_API_KEY=test`; `global-setup.ts` refuses to run unless the fake sees the first translation, so nothing reaches real OpenAI. A fixture is chosen by a `[fx:name]` marker in the typed text (`e2e/fixtures/results`). Environment: `E2E_WORKERS` (default 3), `E2E_PORT_OFFSET` (run two suites at once), `E2E_SERVER_LOGS=1`, `E2E_APP_DIR` (serve another checkout's app). In CI each failed test retries twice and is reported as flaky when a retry passes.

The full suite is heavy: run one tag or one spec at a time on a developer machine (`npx playwright test -c e2e --grep @core`, or a spec file with `--project chromium-portrait`). `@visual` runs only through the visual scripts, `@prod` only with `PROD_URL` (billed), `@review` only with `KEYBOARD_REVIEW=1` (screenshots and video of the keyboard behaviours for manual review).

The visual regression suite captures every state in `e2e/visual/states.ts` as a screenshot, ARIA snapshot and normalized DOM snapshot (`e2e/visual/dom.ts`). Baselines live in `test-results/visual-baseline/` and are never committed (they depend on the machine's fonts). Only `npm run e2e:visual:update` writes them; `npm run e2e:visual` compares and refuses `-u`. To review a change, write baselines from the commit to compare against (a worktree of `master` with `E2E_APP_DIR`, or checking it out), then compare the change.

The perf harness (`npx tsx e2e/perf/measure.ts --fake --runs 10 --out <file>`) measures page load, first typeable, translation latency and keyboard-open layout movement against the fake; `--live --url … --i-understand-this-is-billed` measures a deployment and is billed. `e2e/perf/table.ts` renders reports; the reports under `docs/superpowers/reports` are history.

## Commands

Go comes from your own install (`go.mod`'s `go` line is the requirement); templ comes from the `go.mod` tool directive. Use npm (not another package manager) for the tooling: `npm ci` installs tailwindcss, lucide-static, Playwright, promptfoo and the TypeScript toolchain. Commit `package-lock.json` with dependency changes.

- Run locally: `OPENAI_API_KEY=… go run .` (http://localhost:3000; `PORT` overrides).
- Generate: `make generate` (icons from lucide-static, templ output, Tailwind `app.css`); `make icons`, `make templ`, `make css` individually. Generated files are committed.
- Check: `make check` (regenerate and fail when a committed generated file is stale), `make size` (gzip budgets of the page's scripts and stylesheet), `make test` (`go vet ./...`, `go test ./...`, `node --test 'web/static/js/*.test.js'`).
- Tooling: `npm run typecheck` (e2e and evals), `npm test` (perf-harness unit tests), `npm run format` / `npm run format:write` (prettier).
- Golden request bodies: `go test ./internal/prompt -update` rewrites `shared/translation/fixtures` from `BuildRequest`. Only for a deliberate prompt/schema change, together with a `cacheVersion` bump in `shared/translation/meta.json`; never to make a refactor pass. After editing anything in `shared/translation/`, run `go test ./...`; the embed picks up the files directly.
- Browser tests: `npx playwright install chromium webkit` once, then `npm run e2e -- --grep @core` (one tag or spec at a time). Replay a failed run with `npx playwright show-report test-results/e2e-report`.
- Visual regression: `npm run e2e:visual:update` writes baselines, `npm run e2e:visual` compares. Both accept Playwright arguments, e.g. `-- --project chromium-portrait --grep sentence-done`.
- Production smoke (real, billed OpenAI requests; no retries, no content printed): `go run ./cmd/smoke -url https://<domain> -translate` (time to headers, first frame, first main delta, main-ready, done; fails on a buffered or compressed stream) and `go run ./cmd/smoke -url https://<domain> -speech`. Browser: `PROD_URL=https://<domain> npx playwright test -c e2e --grep @prod --project chromium-macbook-14` (one translation and one real pronunciation). The LRU answers a repeated text in one burst, which counts as a failure; use a fresh synthetic sentence (`-text`, `PROD_SMOKE_TEXT`).
- Quality eval (promptfoo, billed): `npm run eval:quality` compares the variants (OpenAI model + reasoning effort + service tier) in `evals/promptfooconfig.yaml`, running the production request body (printed by `cmd/request`, posted by `evals/translationProvider.ts`, validated against `shared/translation/schemas` with ajv) on the synthetic `evals/cases.yaml` (weighted to the real EN↔KO use: reading Korean news/healthcare/coworker text, writing natural Korean to coworkers/friends/partner, Korean grammar learning, Korean-UI English learning; `situation` is judge-only) and `evals/injection.yaml` (prompt-injection cases that must be translated, never obeyed). Each output gets deterministic `checks` (`evals/checks.ts`, using the app's own `learning.Prepare` through `cmd/request -prepare`), blind `translation`/`explanations` rubric scores (`evals/rubrics.ts`, judge `openai:responses:gpt-6.1-sol`) (no select-best: promptfoo presents variants in config order and the judge favoured the first, so `npm run eval:summary` ranks variants from these scores with ties split). Translations and judge calls are cached by full request (prompt, schema, model, reasoning, repeat index), so adding a variant or rerunning only pays for new calls; `eval:quality:fresh` bypasses the cache (run one eval at a time: concurrent runs share promptfoo's single judge-cache file and can overwrite each other's new entries), `eval:quality:repeat` runs 3 repeats before trusting small differences, `eval:injection` runs only injection cases, `eval:ci` runs the CI config, `eval:progress` reports a running eval, `eval:summary` prints the per-variant table and `eval:view` opens the results grid. Requires `OPENAI_API_KEY` in `.env.local` and Go on `PATH` (the provider builds `cmd/request` once per run); translations and the judge (low reasoning) are paid from the OpenAI credit. The judge shares a model family with the candidates (and is the sol variant), so read small sol leads with care; scores before 2026-10-30 came from Claude Sonnet and are not comparable. Translation responses are cached one file per request in `.promptfoo-cache/translations` (promptfoo's single-file cache lost entries to the CLI's own cache instance). Cases must stay synthetic, never real user text.

## CI

- `.github/workflows/ci.yml` (no secrets, no billed requests; skipped for PRs that touch only docs, Markdown or evals): the unit job runs `go vet`, `go test`, `make check`, the client module tests, the tooling typecheck/tests and `make size`; the e2e job runs each tag on macOS (system fonts and the WebKit build matter for geometry) with one worker and CI retries; the visual job runs on demand (Actions → CI → Run workflow), taking baselines from the `base` input's app (default `master`) and comparing the checkout.
- `.github/workflows/translation-eval.yml` runs `evals/ci.promptfooconfig.yaml` (production config only; keep it in sync with production `TRANSLATE_MODEL`/`TRANSLATE_REASONING`/`TRANSLATE_SERVICE_TIER`) on PRs touching the model-facing request (`internal/prompt`, `cmd/request`, `shared/translation`) or evals, and on demand, failing only when the suite pass rate drops below 60% (terra passes 66–76%, the old luna setup 34–42%; per-case judge failures are expected). It also typechecks the eval code. Billed (about $1 per run before cache hits); needs the `OPENAI_API_KEY` repository secret.
