**TS failures.** All 6 are `context.spec.ts` "Clear input preserves the context and focuses the source": after Clear, `sessionStorage` `nt.context` is empty instead of the typed context. This is the TS reply-context loss recorded in Task 14b (the user decided to leave it; section 5). In this run it hit 6 of 18 projects, mostly the wider and landscape layouts. The largest groups: `layout.spec.ts` tests that set their own viewport run once per engine (240 each); posture emulation is Chromium-only (63); keyboard review evidence only with `KEYBOARD_REVIEW=1` (36); per-layout conditions (desktop workspace only, compact only, phones only). TS has 162 more skips than Go, all TS-only declared skips: early typing (90; TS hydration wipes the text), the `/speech` endpoint tests (36; TS speech is a server function), the analytics form fields (18; TS sends them in a server-function payload) and `stale events from a superseded run cannot touch the result` (18; it dispatches the Go `nt-*` events).

## 2. Visual comparison

`E2E_WORKERS=2 npm run e2e:visual -- --output test-results/visual-signoff`: the TS production build writes fresh baselines (504 tests: 362 passed, 142 skipped by each state's declared projects). Go is then compared with them: an exact DOM snapshot, the ARIA template and full ARIA tree, and screenshots with a 0 px budget, for every state in `e2e/visual/states.ts` on every applicable project.

**Go: 352 passed, 142 skipped, 10 failed. All 10 are accepted below; none is a markup or style change Go should make.**

1. **`settings-open` on all 9 WebKit projects (ARIA + DOM; pixels equal).** TS has four unnamed `button`s around the Settings dialog, and the dialog has `tabindex="0"`; Go has neither, and Chromium passes on all 9 projects.
   - Cause: Floating UI's `FocusGuard` (`@floating-ui/react`) gives its hidden focus-guard spans `role="button"` only when `isSafari()`, a VoiceOver workaround ("On Safari, only buttons trigger the onFocus event"). Elsewhere they are `aria-hidden`. The Safari branch also leaves the floating element in the tab order.
   - Ruling: allowed. It is the already accepted "own `span[aria-owns]` instead of Floating UI's guard/marker spans" difference (Task 24), seen in the WebKit ARIA tree. Go's Settings is a native popover with its own focus handling and needs no guard elements.
   - The task-level visual runs used 3-project subsets (ledger), which is why this appears only now.
2. **`learning-open` on `webkit-landscape` (pixels only: 3,907 px, a 6 px vertical offset; DOM and ARIA equal).** Deterministic in both apps (Go 3/3 repeats; TS 3/3 against its own baseline).
   - At 580×382, before the row tap, the second phrase row sits 6 px below the panel's visible area in both apps (identical geometry, measured). Playwright's click scrolls it into view (`scrollTop` 6) in both.
   - TS then returns the panel body to `scrollTop` 0. No TS code does this (instrumented `scrollTop`, `scrollTo`, `scrollBy` and `scrollIntoView`: none touched the panel). It is WebKit's response to React removing the previous row's details node and inserting the new one. Go toggles `hidden` on details that stay mounted (the accepted "mounted-but-hidden" approach), so the 6 px scroll remains.
   - Ruling: allowed. It appears only when the tapped row was partly scrolled into view, it leaves the selected row fully visible in both apps, and Chromium is equal.

Diff images and actual/expected files: `test-results/visual-signoff/` (git-ignored). The run log is kept with the sign-off notes.

## 4. Allowed Go-vs-TS differences

From the ledger's sign-off list, with the task that accepted each. None changes final markup, and the visual run (section 2) found no difference outside this list.

**Streaming and timing**

- Dictionary sections appear when their JSON value completes (value-end granularity) instead of streaming partial strings; final markup identical. (Task 15)
- `#word-meta` swaps use `innerMorph` (no replayed animations). (Task 15)
- Pending dictionary skeleton follows POS 0, not the active tab (only when switching tabs mid-stream and a completed POS has an empty first definition). (Tasks 15/17)
- Reduced motion: Go skips the view transition entirely; TS still runs the browser's ~250 ms root crossfade (only the result transition is cancelled), so toolbar changes fade in TS and switch instantly in Go. (Task 16)
- The final alternative row is swapped in before the `nt-done` transition snapshot (no 160 ms fade for that row); TS settles it inside the transition. (Task 16)
- Aborted run mid-alternatives: Go leaves the pending skeleton until the next run starts; TS renders the (possibly complete) row. Both show a stale aborted result. (Task 16)
- Register label mode comes from the run's tone, not the live tone during the debounce window. (Task 16) Main `lang`, register language and speech language now follow `nt-target-lang` as in TS (closed in `1d0a47c`).
- Error text is not relabelled on a UI-language switch during the debounce window (TS also keeps the input-error text in the old language). (Task 16)
- A whitespace-only source edit hides learning for the debounce window (≤ 800 ms) until the cached re-run; TS keeps it visible. (Task 19)

**Mounted-but-hidden instead of unmounted**

- Reference pane parked in a hidden `#reference-dock` instead of unmounting. (Task 15)
- POS tabs: one server-rendered `hidden` block per POS with `data-pos` instead of client state. (Task 15)
- Reply-context field rendered from a `<template>`; toggle tone via `data-active-class`. (Task 14b)
- Learning rows live in a permanent hidden `#learning-sentence` (`innerHTML`) instead of an outerHTML swap of `#learning-inspector`. (Task 19)
- Learning panel stays mounted `hidden`, `data-expanded` only while open. Pagehide also closes the word surface (TS: sentence state only; invisible). (Task 25)
- Listen and swap icons: all variants mounted, inactive ones `hidden`. (Tasks 16/23)

**Menus and focus**

- More menus: ArrowDown when the first option is already active focuses it in Go; TS leaves focus on the list (a React `setState` no-op quirk). (Task 24)
- Own `span[aria-owns]` instead of Floating UI's guard/marker spans; native `popover="auto"` (focus returns to the trigger after an outside press only when it fell to `body`). (Task 24)
- Compact synonym lookup: Go focuses the source; TS loses focus to `<body>` (TS bug: `focus()` on an inert textarea). (Task 17)

**Server**

- `/speech` with a missing key → 500 with the configuration message (the client shows `speechFailed` in both apps). (Task 22)
- Indic conjunct grapheme boundaries (see (c)). (Task 18)

**Harness**

- The DOM snapshot ignores Go-only hooks: `data-t*`, `hx-*`, `data-active-class`, `data-icon`, `data-pos`, React `vt-*`, `id`, `style`, `popover*`. (Tasks 14b/15)

**Found by the full WebKit visual run (Task 32, section 2)**

- WebKit only: TS exposes Floating UI's Safari focus guards as four unnamed buttons around the open Settings dialog, which has `tabindex="0"` there; Go has neither (native popover, no guard elements).
- WebKit landscape only: after a tap on a phrase row that Playwright first scrolled 6 px into view, Go keeps the learning panel's 6 px scroll; WebKit resets TS's to 0 when React replaces the details node.

**TS bugs the Go app does not have (declared in the suite)**

The suite marks these TS behaviours with `test.fail(APP === 'ts', …)` or a TS-only skip, so they count as expected outcomes on TS and as normal passes on Go:

- `cmd+enter replaces the pending debounce`: in TS the forced run leaves the 800 ms debounce armed, which aborts the forced run and sends a second, paid request.
- `error kinds are localized`: in TS the AI SDK streaming path surfaces upstream HTTP errors without a cause, so every kind shows "Translation failed." (budget, rate limit, auth and model errors are not distinguished).
- `IME composition is not interrupted` (Chromium, CDP IME): in TS every composition update re-arms the debounce, so a paid run fires on partial jamo while the user is still composing.
- `text typed before the modules run is translated once` and its reload/back-forward variants: TS hydration wipes text typed before it runs (TS skip); Go keeps and translates it on fresh navigations only (`1992739`).
- `stale events of a superseded run cannot touch the result`: Go-only (it dispatches Go's `nt-*` events directly).

**Platform (documented elsewhere, not on the ledger list)**

- Vercel does not cancel a Go function when the browser disconnects (stage 0; `go/README.md`): a superseded translation runs upstream to completion, while TS sets `supportsCancellation: true`. In the Task 31 measurements (30 interaction runs per app) Go sent no superseded request (90 sent, fake and live), against TS's 12 (fake) and 14 (live). Locally (and in every e2e test) the Go server does cancel upstream (`editing mid-stream cancels upstream`, `TestClientAbortCancels`).
- The Go function runs in Vercel's default region `iad1`; TS runs in `icn1` (ruling recorded in the performance report).

## 5. Shared behaviours left as they are in both apps (user decisions)

## 6. Manual checks (not automatable here)

The suite simulates touch, keyboards and folds. These need real devices or browser flags:

1. **Real iOS touch** (iPhone Safari): the long-press callout and text-selection handles on the main text and the source; a pan that ends in `pointercancel` must not inspect; double-tap zoom must not inspect; handle drags keep native selection. (Task 20)

WebKit has no posture emulation, so the fold tests skip there by declaration. Also a real dual-screen device (e.g. Surface Duo, 1114 × 720 book) for the shared Paste/Clear dock fix. (Tasks 27/28)
